# Notes for agents

Surprises in this project that cost time. Add to this list when you hit another.

- **Docker over `DOCKER_HOST=ssh://...`:** bind-mount paths resolve on the Docker *host*, not on the machine running compose, so `../output` would mount an empty directory there. `docker/compose.yaml` therefore requires an absolute `KOTOBA_DIR` (in gitignored `docker/.env`). Data must be copied to that directory on the host first.
- **`OLLAMA_*` belong in `docker/.env`, not `.env`:** the compose `environment:` block overrides `env_file` and is interpolated from `docker/.env`, so a value in `../.env` is silently ignored.
- **`TZ` must be set in `.env` for Docker:** output filenames use the local date (`toLocaleDateString`), and the container runs in UTC.
- **Windows checkouts have CRLF files.** Diff with `--strip-trailing-cr`, and strip `\r` before copying a `.env` (`tr -d '\r'`).
- **`OLLAMA_HOST` means two things:** for the Ollama *server* it is a bind address (`0.0.0.0` = listen on all interfaces); here it is the *client* URL (`applyEnvOverrides` in `src/config.ts`). A Windows user env var `OLLAMA_HOST=0.0.0.0`, set so other machines can reach Ollama, is inherited by a local pipeline run, which then dials `http://0.0.0.0:11434`. Windows refuses that, so translation logs "No translation provider available" and the site is published with no English. That is how translations vanished on 2026-09-25 (in Docker, `docker/.env` sets a real host, so it is unaffected).
- **The Ollama server (`dtop.home`) is shared:** hermes' Hindsight memory service (`qwen3.6-27b-ctx131k`) and hermes cron jobs use it too, and two 17 GB models don't fit at once. Hindsight fires an LLM retain/consolidation right after each hermes cron finishes (the 06:00 `substack-digest` ends about 06:08), which made a translation time out on 2026-09-29. The schedule is 05:00 to stay ahead of those, and `translateOllama` retries with a 120s timeout. Before moving the schedule, check `~/hermes/data/cron/jobs.json` on nuc1.
- **One scheduler at a time:** `output/kotoba.db` is the dedup state. The Windows task `KotobaPipeline` and a scheduler on nuc1 must not both run against separate copies.
- **The scheduler is supercronic, not the image's ENTRYPOINT:** `kotoba-scheduler` overrides the entrypoint to run `docker/crontab`. One-off commands use the `kotoba` service (profile `tools`), which keeps the `node dist/index.js` entrypoint. The cron schedule is baked into the image, so changing it needs `up -d --build`.
- **`npm run dev` does not work.** The sources import siblings as `./config.js` (as `tsc`'s output needs), and ts-node's CommonJS hook does not map that back to `config.ts`, so `ts-node src/index.ts` dies with "Cannot find module './config.js'". Use `npm run build && npm start`. The tests get around it with `test/register.cjs`, a small resolver hook loaded with `node --require`; `npm test` already does this.
- **Tests must not see your shell's environment.** `OLLAMA_HOST`, the API keys and friends change results (see the `OLLAMA_HOST` note above), so tests call `setEnv()` from `test/helpers.ts`, which clears them. Do the same in any new test that loads config or picks a provider.
- **`dictionary.ts` keeps state per process.** Failure counters and the throttle slot are module-level, and a tripped Jisho abort stays tripped. Tests load a fresh copy with `delete require.cache[...]`; in `pipeline.test.ts` the outage test must stay last.
- **`todo` tests are known bugs, not clutter.** They run and assert the correct behaviour without failing the suite; see `docs/TESTING.md` for the list. When you fix one, delete its `todo` option.
- **Fixture text must be over 200 characters to count as "inline".** `resolveArticleText` and the feed parsers use a feed's body only when it is longer than 200 characters, and otherwise scrape the page. Japanese is compact, so a short test article silently turns into a request for a URL that returns 404. Repeat the text or pad it.
- **A scraped content selector needs over 100 characters of text.** `extractText` skips `article`, `main` and the rest if they hold less, and falls back to `<body>`.
